# Crosscheck 通用工具最终验收基线

版本：1.0  
固化日期：2026-11-12  
用途：P0～P2 全部整改完成后的最终验收依据。后续实现不得通过降低本文件标准来宣称完成。

## 产品定位

Crosscheck 应成为面向企业 Web 业务系统的通用测试编排与跨层验证平台内核：

```text
通用测试内核
+ 标准用例语言
+ 项目连接器
+ 业务状态/数据配方
+ Agent 自动编排
```

它不承诺“任意系统、任意自然语言、零配置自动测试”，但必须做到不修改 core 即可通过连接器和配方接入不同企业业务系统。

## 目标用户体验

用户提供 Excel、case-gen YAML、PRD、OpenAPI、数据库 schema 或已有环境后，系统应自动：

1. 归一化为 canonical suite；
2. 校验用例完整性和来源；
3. 识别要求的 UI/API/DB/事件/角色层；
4. 绑定套件内连接器和配方；
5. 编译成确定性、不可变执行计划；
6. 将无法编译的部分标记为 DRAFT/BLOCKED/INVALID_SPEC；
7. 运行 Pilot；
8. Pilot 和安全门禁通过后自动批量执行 READY；
9. 自动准备和清理测试数据；
10. 输出断言级证据和未覆盖原因。

不得出现每一步都询问用户、同 ID 串入旧规格、通用列表对账冒充复杂业务通过、空数据一致冒充完整验收、Skill 与 CLI 行为不一致。

## 能力目标

### 成熟能力

- 企业 Web 列表、详情、搜索、筛选和分页；
- API 契约、参数、负向、幂等和数据库一致性；
- 页面/API/DB 跨层验证；
- 有配方的 CRUD、状态机和自动清理；
- 截图、DOM、录像、请求、响应、SQL 和清理证据；
- 套件隔离、角色绑定、审批哈希和可恢复流水线。

### 依赖项目配方的能力

- 多角色审批、转办、退回、撤回；
- 数量、金额和组合规则；
- 异步任务、消息和跨系统回写；
- 整体失败、禁止部分成功和权限变化。

### 需要专用适配器的范围

- 原生移动端、桌面客户端、硬件设备；
- 性能/容量/压力和专业渗透测试；
- MQ、邮件、短信、文件批处理和非 HTTP 系统；
- 视觉质量、音视频、地图和 3D 等特殊领域。

## 结果真实性门禁

用例仅在所有必需前提和断言真实执行成功后才能 CASE_PASS。以下情况绝不能 PASS：

- 没有断言；
- 必需 fixture 未准备或未验证；
- 预期有目标数据但页面/API/DB 均为空；
- 抓到错误接口或参数不匹配；
- 只完成通用一致性，但未执行用例专用业务判据；
- 必需层缺失；
- 清理失败、未声明表变化或登录身份不匹配；
- 计划内容变化后仍复用旧审批；
- 用例和 spec 的 suite/source/hash 不一致。

统一终态：CASE_PASS、CASE_FAIL、PARTIAL、BLOCKED、INVALID_SPEC、ENV_ERROR、NOT_RUN。

## 通用性最终验收

1. 选择两个完全无关的业务系统；
2. 不修改 core；
3. 仅增加各自 suite、连接器、fixture 和 oracle；
4. 同一流水线完成导入、编译、Pilot、批量、UI/API/DB、清理和报告；
5. 同编号用例不能跨套件污染；
6. 空数据、错误接口、错误角色、错误断言不能 PASS；
7. 清理失败停止相关后续写入；
8. 流水线中断后可以恢复；
9. case-gen 标准 YAML 可直接导入；
10. 未完成绑定的用例只能是 DRAFT/BLOCKED/INVALID_SPEC。

## 量化验收指标

- Schema 合规率；
- 编译成功率；
- 业务充分率；
- 前提就绪率；
- 实际断言覆盖率；
- 自动推进率；
- 清理成功率；
- 跨业务不改 core 验收结果。

成熟度不得再使用主观综合分替代上述指标。最终报告必须逐条引用自动测试、负向实验和运行证据。
